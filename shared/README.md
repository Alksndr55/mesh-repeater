# Общая схема Mesh Repeater

**Ведущая схема и разводка - v1.** Электрические решения принимаются на основе v1; v2 реализует ту же схему на POWER и LOGIC с собственной геометрией. Текущая общая схема получена из принятой v1.22. Проводники, переходы, площадки, размещение и заливки существующих PCB при её создании не менялись.

Откройте [`schematic/MeshRepeater.kicad_pro`](schematic/MeshRepeater.kicad_pro) в KiCad 10. Это редактируемая общая принципиальная схема из восьми листов, 150 функциональных позиций. [`output/pdf/MeshRepeater_schematic.pdf`](output/pdf/MeshRepeater_schematic.pdf) - её экспорт. Локальные символы, используемые посадочные места и собственные 3D-модели включены. Стандартные модели `${KICAD10_3DMODEL_DIR}` берутся из обычных библиотек KiCad 10.

Native-файлы в `shared/schematic/` являются единственным источником электрической схемы: связи выводов, номиналы, MPN функциональных компонентов и три варианта комплектации. `model.json` в каталогах плат - вспомогательные данные, проверяемые на соответствие native-схемам; отдельная общая модель со вторым набором номиналов не создаётся.

## Физические исполнения

[`variants.json`](variants.json) задаёт только различия исполнения: распределение общих позиций между платами, локальные посадочные места и MPN внешних соединителей/кнопок, сокращения подписей и разрешённые дополнительные элементы. В v1 четыре монтажных NPTH; в v2 монтажные GND-контакты, дополнительная точка TP6 и пара J101/J201. J12 имеет три контакта у v1 и четыре у v2; четвёртый контакт v2 явно NC. На схеме нет монтажных H1-H4, потому что их физический смысл разный у двух конструкций.

В v2 физические контакты J101/J201 соединяются 1:1. В проверке объединяются только одноимённые контакты этой пары; R71 и NT2 не закорачиваются виртуально. BAT/BAT_SYS и SYS/RADIO остаются отдельными группами выводов общей схемы. Контакт 8 межплатной пары остаётся NC.

Существующие схемы в каталогах каждой PCB являются физическими проекциями общей схемы. **Они пока не генерируются автоматически.** Идентичность подтверждает строгая проверка; документ не обещает автоматическую синхронизацию проводов.

## Изменение схемы

1. Принимать решение в ведущей v1: проверить электрический смысл и влияние на её компоновку. При конфликте прежних материалов основой служит v1, затем её утверждённое решение отражается в общей схеме.
2. Внести принятое электрическое изменение в `shared/schematic/`, сохраняя позиции и номера выводов. На схемах плат вручную перенести только соответствующие номиналы, поля и соединения. Сохранять существующие UUID символов и иерархические пути, чтобы не потерять привязку к принятой PCB.
3. `variants.json` менять лишь при обоснованном изменении физического исполнения. Нельзя добавлять в профиль обход для несовпавшего функционального номинала или связи. Посадочные места не переносить между v1 и v2 автоматически.
4. Запустить проверку ниже. Она экспортирует новые native XML, сравнивает полные группы выводов, значения, комплектацию, физические профили и доступные модели; выполняет ERC общей схемы. Любая несогласованная правка блокирует выпуск.
5. Отдельно выполнить ERC схем каждого изделия и DRC с проверкой паритета каждой PCB. Если электрическое изменение действительно требует разводки, редактировать каждую PCB отдельно, начиная с v1. Не запускать исторические генераторы S4/A2/A3 над текущими исходниками.
6. Экспортировать актуальную PDF общей схемы и включить её в оба выпуска. Геометрию и производственные файлы выпускать отдельно для каждого изделия.

## Проверка

Из корня проекта:

```powershell
python tools/project/verify_circuit.py --out shared/verification
python tools/project/verify_circuit.py --product v1 --out shared/verification/v1
python tools/project/verify_circuit.py --product v2 --out shared/verification/v2
```

`--product` можно повторять. Без него проверяются изделия из `project.json`. Опции `--config` и `--kicad-cli` позволяют проверить переносимый пакет. Пакет v2 не требует установленной рядом рабочей v1: он содержит общую схему и свой профиль, а отметка о ведущей v1 сохраняет происхождение решения.

`circuit.json` в указанной папке содержит итог PASS/FAIL, команды, все различия и SHA-256 исходников. XML и ERC рядом получены свежим экспортом. Проверка не меняет native-схемы, модели или PCB; она дополнительно сверяет сохранность их байтов. Если `--out` не указан, результаты сохраняются во временной папке ОС.

Текущий контрольный результат: [`verification/circuit.json`](verification/circuit.json). Эта проверка доказывает соответствие схем и не заменяет DRC, проверку производства или измерения собранного устройства.
