# Mesh Repeater: единое управление v1 и v2

Обе версии ведутся из этого каталога и чата `01a13688-a487-7f53-853b-c371e805b46f`.
Решение владельца от 24.10.2026.

- **Ведущая разводка — v1.** Электрические решения и компоненты сначала проверяются
  в v1. v2 получает те же функциональные изменения с адаптацией к POWER/LOGIC.
- Общая электрическая схема: `shared/schematic/MeshRepeater.kicad_pro`.
  Физические различия описаны в `shared/variants.json`. Платы сохраняют свои UUID,
  посадки и геометрию; проверка выпуска сравнивает их с общей схемой.
- Владелец разрешил управление обеими версиями. Прежние ограничения на перенос
  между ними заменены этими правилами. Результат задачи должен отражать перенос
  и проверку каждого затронутого исполнения.
- Номера и текущие проекты задаёт корневой `project.json`. Формат: `v1.XX` и
  `v2.XX`, минимум две цифры после точки. Текущие версии — v1.26/v2.10;
  следующие номера — v1.27/v2.11. Старые опубликованные теги не переименовывать.
- Единый процесс выпуска: `docs/WORKFLOW_RU.md`. Текущие команды — `tools/project`.
  Не запускать исторические генераторы поверх принятой нативной разводки.
- Перед выпуском обязательны проверка общего графа, BOM, ERC, DRC и соответствия
  схемы PCB. Не скрывать нарушения исключениями. Прежние отчёты не проверяют новые файлы.
- В каждой будущей сборке v1/v2 обязательны по два boardview `.cad` для каждой
  физической платы: натрий `NaIon_COLD` и `LTO_2S`. Генерировать из текущей PCB
  через `tools/project/release.py`; номиналы/маркировки и DNP брать из модели/BOM
  соответствующей сборки. DNP-площадки сохранять. Использовать GenCAD THOU для NexusBV.
  CAD и проверка его соответствия точной PCB входят в ZIP и манифест SHA256;
  отсутствие, устаревшие данные или ошибка проверки останавливают упаковку.
- В каждый ZIP v1/v2 включать portable NexusBV из `third_party/NexusBV/0.9`
  вместе с исходными сведениями об авторе и фиксированным SHA256-манифестом.
  Корневой `START.cmd` и отдельные запуски каждой платы/химии открывают CAD
  и соответствующую PDF-схему из распакованного пакета по относительным путям.
  Не включать личные настройки, историю, базы пользователя и конвертеры Cadence.
  Отсутствующий или изменённый файл программы блокирует выпуск.
- PDF для NexusBV получают невидимые области выбора по телу символов через
  `release_pdf.py`; существующий текст сохраняет приоритет. При каждом экспорте
  проверять неизменность изображения всех страниц, координаты областей и
  привязку отчёта к текущим листам схемы и PDF. Ошибка блокирует упаковку.
- Все используемые 3D-модели включаются в каждый пакет с относительными путями
  `${KIPRJMOD}` и исходными лицензиями. Это относится и к стандартным моделям
  KiCad. Внешняя `${KICAD...}`-зависимость в PCB или используемой посадке
  блокирует выпуск; установленная библиотека на компьютере автора не является
  доказательством комплектности скачанного архива.
- Пакеты и расчёты заказа для Резонита удаляются по решению владельца; новые
  пакеты для него не создавать. Производственный экспорт выполняется отдельно.
- Сохранять лицензии, нужные даташиты, watchdog и актуальные закупочные сведения.
  Окружения `tools/cad3d` и `tools/routing` не переносить автоматически.
- Обычный ясный язык; Caveman только по прямому запросу. Интернет по умолчанию
  через Firefox Bridge, обнаруженный по имени, независимо от транспортного семейства.
- Для GitHub по умолчанию использовать API; Git — для локальных коммитов и push.
  Это исключение из общего правила Firefox, принятое владельцем 30.10.2026.
- Дорожки и GND-переходы обрабатывать по `docs/ROUTING_RULES_RU.md`:
  сначала удалить все GND-vias, затем привести дорожки к правилам и устранить
  дубли, затем добавить земляную сетку 5 мм. Внесеточные точки требуют
  записанной электрической причины. Сохранять расстановку и критические узлы.

- Нулевой DRC не является приёмкой стиля: полные трассы и зазоры групп
  проверяются с обеих сторон. `routing_review.json` привязан к точному PCB;
  проверка выпуска сверяет геометрию, сетку и каждое её исключение.
