# Проверка сохранённых схем и плат 2.0

`tools/verify_v2_native_boards.py` читает сохранённые model.json, нативные платы KiCad, экспортированные XML обеих схем, электрический контракт S4.16 и актуальную карту 12-контактного кабеля. Платы, схемы и библиотеки скрипт не изменяет; записывается только отдельный JSON проверки внутри 2.0.

Для проверки GPIO используется хеш-проверенная копия оригинального native netlist: `audit/source_s4_16/native_netlist.xml`. SHA256 `14b479e30ab779ca2c8af2465e6ccee1ccf8aeb26e435c4c3a84bb1cc51662d3` совпадает с источником контракта. Проверка переносима вместе с каталогом 2.0 и не требует старой рабочей папки 1.0.

Запуск из рабочей папки версии 2.0 (`Meshcore/v2`) в PowerShell:

```powershell
& 'C:/Program Files/KiCad/10.0/bin/python.exe' tools/verify_v2_native_boards.py --stage snapshot
```

После сохранения окончательных плат и нового экспорта XML:

```powershell
& 'C:/Program Files/KiCad/10.0/bin/python.exe' tools/verify_v2_native_boards.py --stage final --out audit/v2_native_boards_final.json
```

Если каталог 2.0 открыт непосредственно, используют относительный путь `tools/verify_v2_native_boards.py` и выход `audit/v2_native_boards_final.json`. Python должен содержать модуль pcbnew соответствующей версии KiCad.

Проверяются точные составы reference/pin, идентификаторы посадочных мест, номиналы, стороны, координаты и углы против моделей; все Fit/Value/MPN электрических деталей трёх вариантов; локальные группы выводов платы против модели и native XML; общий функциональный граф S4.16 после соединения кабеля 1:1. Для M1/M2 отдельно сопоставлены имена и типы всех физических выводов оригинального и нового native XML, включая GPIO Nice!Nano. Также проверяются исходная посадка J10 и разделение назначенных сетей J11. В ревизии A2 контакт 7 межплатных разъёмов возвращает SYS_3V3 с LOGIC на POWER только для питания INA219 и его развязывающего конденсатора; FILTER_OUT остаётся отдельной сетью. В прежней A1 SYS_3V3 среди межплатных контактов отсутствовала.

Индивидуальные графические посадки с суффиксом `__V2_<ref>` допускаются только по точной карте `audit/MeshRepeater2_*_footprint_variants.json`. В ней требуется совпадение исходной физической посадки, новой посадки и хешей сохранённых библиотечных файлов; геометрия площадок, Fab, courtyard, 3D, корпуса и MPN остаётся прежней. Изменение физической посадки нельзя скрыть этой картой. Для J10 сравнение с S4.16 использует именно исходную физическую посадку.

Допустимы только явно согласованные механические отличия: удалённый SH1, открытые GND-контакты H1–H4, дополнительные верхние крепления и межплатные разъёмы, четвёртый NC-контакт J12. Номиналы электрических деталей и функции выводов исключением не покрываются.

На окончательном снимке 11 октября 2026 года прошли 201 из 201 условия, в том числе две проверки карт графических посадок. Проверка повторена после последнего экспорта XML обеих схем. Актуальность результата определяется хешами входов; их изменение во время чтения считается ошибкой. Окончательный результат хранится в `audit/v2_native_boards_final.json`; после дальнейшего редактирования нужен новый запуск.

Эта проверка подтверждает идентичность компонентов и **назначенных сетей**. Наличие маршрута между площадками, отсутствие физического медного обхода J11, коротких замыканий, производственные зазоры и завершённость трассировки подтверждаются отдельно DRC и проверкой связности. Режим `final` отмечает финальный снимок этой проверки; он не является разрешением производства или подтверждением EMI, нагрева, фактической сборки и работоспособности образца.
